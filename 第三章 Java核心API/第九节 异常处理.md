## 异常与程序控制

程序的运行始于main方法的调用，终于main方法运行完成。在这个过程中，程序通过方法调用、对象创建与销毁等，层层运行。因此，运行到任何一处代码块(方法、构造器、初始化块)，必然可以向前追溯到调用这个代码块的代码(姑且称为其"上级"吧)，以此类推

因此，代码运行时很有可能出现异常，但当前代码块处理不了这个异常。这可能是因为访问权限等诸多因素，所以我们便需要将这个异常交给上级代码处理

这就是异常的**抛出**

异常其实就是一种类和对象。只不过异常必须继承自`Throwable`(可抛出，你没看错)。`Throwable`类有两个子类：`Error`和`Exception`。

其中，`Error`的严重性高于`Exception`，一般而言你也不需要处理，只要想办法让程序尽快安全结束即可。`Error`的常见子类有`OutOfMemoryError`(爆内存)和`StackOverflowError`(爆栈)等

异常处理涉及的关键字包括：`try` `catch` `finally` `throw` `throws`。当然还有`new`

## try-catch-finally块

当一个异常被抛出，jvm会逐层回溯这个异常抛出处的上级，直到找到一个try块。若未找到try块，则程序异常结束，俗称崩溃

下面我们讲解try-catch-finally块：

我们假设存在方法`readConfig();`，且这个方法**可能**抛出一个`NullPointerException`，那么我们必须要拦截这个异常，语法如下：

```
try {
    readConfig();
} catch (NullPointerException e) {
    System.out.println("Failed to read config.");
    e.printStackTrace();
} finally {
    System.out.println("Finished reading config.");
}
```

其中try块内包裹的是可能出现异常的代码

catch块要求带一个参数，这个参数是你要检索的异常类型。同时，catch块允许收多种异常，只需要用竖线分隔不同类型：

`catch (类型1|类型2|其他zzz e)`

注意这里也符合OOP的核心特征，即存在多态性

除此之外，catch块允许有多层：
```
try { /*...*/
} catch (FileNotFoundException e) {
    System.out.println("File not found...");
} catch (IOException e) {
    System.out.println("Other IOException...");
} catch (Exception) {
    System.out.println("Unknown exception...");
}
```

对，这里`FileNotFoundException`是`IOException`的子类。多层catch块类似if-elseif语句，逐层进行，因此必须是从小条件到大条件判断

然后最后一块，finally块，是无论是否出现异常，都必然被执行的代码。这里常用于关闭输入输出流等对象

## 受检异常与非受检异常

简单来讲，非受检异常就是`RuntineException`及其子类，受检异常就是除此之外的

如果你的方法、构造器可能抛出受检异常，那么必须用`throws`关键字显式声明，其语法如下：

`方法签名 throws 受检异常1, 受检异常2, ... {/*方法体*/}`

构造器同理

调用显示声明了抛出受检异常的方法时，要不使用try块包围，要不在当前方法再次显示声明可能抛出这个异常
