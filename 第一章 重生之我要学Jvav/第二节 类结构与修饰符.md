# 类结构与修饰符

学习目标：了解Java项目的软件包和类结构，了解各种修饰符，会使用注释
内容要点：

- Java的文件结构
    - 包、类、方法、变量
    - 面向对象的基本理解
- 修饰符
    - 访问控制修饰符
    - final修饰符
    - 初识static修饰符

    - 文档注释
- 注解
- 主类

## Java的文件结构

[代码](../src/tutorial/basic/structure/SimpleClass.java)

```java
package tutorial.basic.structure;

import java.util.ArrayList;
import java.util.List;

public class SimpleClass {
    public static final int A_INTEGER = 200;
    @SuppressWarnings("all")
    protected final List someList = new ArrayList();
    private String someString;

    public SimpleClass(String someString) {
        this.someString = someString;
    }
    
    /*
            一个多行注释
     */

    public String getSomeString() {
        return someString;
    }

    //这里有一个单行注释

    /**
     * 这里对方法add进行注释。
     * @param a 一个形参
     */
    public static int add(int a) {
        int dummy = ++a;  //单行注释可以放在任何地方
        System.out.println("Now we have " + dummy);
        return dummy;
    }
}

```

### 包声明

`package tutorial.basic.structure;`  
这是一条**包声明**语句。Java中，上下级目录之间采用`.`分隔，也就是说这里对应的软件包目录就是`tutorial/basic/structure`。
除非直接在项目的根目录下。类必须有包声明。包声明的作用是避免潜在的同名类的冲突。  
比如我们看到示例代码中，在`tutorial.basic.structure.client`和`tutorial.basic.structure.server`下，均存在名为`EventHandler`
的类。
我们在引用一个不同软件包下地类时，可以用其的软件包作为限定符，如`tutorial.basic.structure.client.EventHandler`和
`tutorial.basic.structure.server.EventHandler`。  
特别的，同包下的类不需要添加这样的限定符。

一般而言，包的命名与类、变量的命名规则是一致的。同时，包命名有如下额外规则：
- 全部小写字母
- 按功能划分软件包
- 使用反转域名。如你的个人网站在`seraphic.dev`时，使用`dev.seraphic`作为根包

### import

```java
import java.util.ArrayList;
import java.util.List;
```

上面我们已经提到，使用不同软件包下的类时，要用其软件包作为限定符。但是这很费劲，所以我们可以使用**import语句**。  
import顾名思义，就是显式声明导入该类，则后续使用中就不需要每次都添加一大堆软件包名。比如这个类中，如果我们不使用导入语句，那么所有的
`List`都要写成`java.util.List`。而导入了List之后，则可以简单的使用`List`。  
特别的，`java.lang.String`和`java.lang.System`已经默认导入，不需要再显式声明导入。  
如果存在两个相同名地类，我们可以对其中一个使用import，另一个就必须用全称了。
```java
import tutorial.basic.structure.client.EventHandler;

public static void main(String[] args) {
    new EventHandler();
    new tutorial.basic.structure.server.EventHandler();
}
```

### 类定义

`public class SimpleClass {...}`
这里定义了一个类。类定义的方式是：`修饰符 类类型 类名 {类体}`。  
修饰符包括主要两类：

- 访问控制修饰符(public, protected, (无), private)
- 非访问控制修饰符(final等)

这里先按下一笔。

类名命名要求如下：
- 不可以字母和下划线以外的ascii字符开始
- 不可与Java关键字相同
- 允许中文、日文等utf8字符

除此之外，类名的习惯命名原则如下：
- 使用ascii字符命名，最好仅用a-zA-Z，可以使用0-9，最好不用下划线
- 类名必须可读，如`LivingEntity` `EnderDragonEntity` `MathUtils`
- 大写驼峰，每个单词的首字母大写，其余字母小写。单词间无间隔

你当然可以不遵循这个命名原则。只要你不怕被同组的入打死

### 字段声明

```java
public static final int A_INTEGER = 200;
protected final List someList = new ArrayList();
private String someString;
```

这一段声明了一大堆**字段**。字段又叫**成员变量**。  
根据是否被static修饰，字段可以分为静态字段和非静态字段(也叫实例字段)。这个概念比较复杂，所以我们这节课之后先一律使用静态字段。
字段就是一个可以储存一些数据的容器。

### 构造器

```java
public SimpleClass(String someString) {
    this.someString = someString;
}
```

这是一个**构造器**。构造器的作用是创建这个类的实例。
再创建类的实例时，我们的语法是`new 类名(形参类型1 形参1, 形参类型2 形参2, ...)`，比如`new SimpleClass("meow")`就会创建一个该类的对象。

### 方法

```java
public String getSomeString() {
    return someString;
}

public static int add(int a) {
    int dummy = ++a;
    System.out.println("Now we have " + dummy);
    return dummy;
}
```

这里我们定义了两个**方法**。方法同样分为静态方法和非静态方法。同样的，这节课以后我们一律使用静态方法。
方法中可以定义局部变量，如`int dummy = ++a;`。局部变量不允许final以外的其他修饰符。

局部变量和字段统称为变量。

方法我们会在下一节展开讲。

### 面向对象的基本理解

当下主流编程范式有面向对象(OOP)、面向过程等。面向过程的代表性语言有C等，面向对象的代表性语言有Java、C#等。除此之外，很多编程语言是多范式的，即可以包含多种编程范式，如C++、Python等。

面向对象的特点在于，我们在代码中可以创建虚拟的"实体"(对象)来代表不同物体。这些"实体"可以拥有自己的行为(方法)和状态(实例字段)。

典型的面向对象的代码执行如下：

```
object.someInstanceMethod();   //调用对象的someInstanceMethod方法

System.out.println(object.someInstanceField);   //访问对象的someInstanceField字段
```

对象的创建需要调用类的构造器。我们使用`new 类名(实参...)`来创建类。我们称某个类的对象为该类的**实例**。

## 修饰符

我们先说访问控制修饰符。

| 修饰符名                    | 可见性             |  
|-------------------------|-----------------|  
| public                  | 任何地方都可见         |
| protected               | 该类的子类、同软件包下的类可见 |  
| *package-private*(无修饰符) | 同软件包可见          |
| private                 | 仅该类内部可见         |

对于同一个类、字段等，只能由一个访问控制修饰符。然而要注意的是，每一个java文件必须包含一个public类。
除此之外，你可以额外增加*package-private*的类。我们一般不这么做，而是采用内部类。这里不需要知道内部类是什么，你只要知道，一个java文件最好只有一个类。

然后是非访问控制修饰符。

| 修饰符名   | 作用                                                                                  |
|--------|-------------------------------------------------------------------------------------|
| final  | 对变量使用时，将其标记为常量(只可以赋值一次，即初始化，后续不可修改其值)；  对类使用时，令其不可被继承；对方法使用时，令其不可被重写。后两种我们会在OOP章节谈论 |
| static | 标记成员为静态。我们现在开始，涉及的一切字段和方法都用static修饰，static和非static的区别会在OOP讲到                        |

## 注释

代码中你应该注意到了这些内容：

```
/*
  一个多行注释
*/
 
//这里有一个单行注释

/**
 * 这里对方法add进行注释。
 * @param a 一个形参
 */
public static int add(int a) {...}

    int dummy = ++a;  //单行注释可以放在任何地方
```

这些就是**注释**。注释的作用是提高代码可读性，方便程序员过几天之后回来理解自己的代码是什么意思。注释在编译时会被忽略。

注释我们也分类看：

| 类型   | 写法                          | 特点                     |
|------|-----------------------------|------------------------|
| 单行注释 | `//注释内容`                    | 从双斜杠开始到行尾，整行都是注释。      |
| 多行注释 | `/* 内容，可以跨行，但是我在表格里打不出来 */` | 可以跨行，从`/*`到`*/`的全部都是注释 |
| 文档注释 | `/** 内容 */`                 | 只能用于方法、类、变量。下面我们会详细解析。 |

### 文档注释

文档注释功能更加强大，其内容允许使用markdown格式和html格式来书写。文档注释一般分为两部分：前半部分和多行注释一样，就是你简单的介绍一下这个方法(
/类/变量)有什么用，后半部分可以用若干标签，对方法进行额外说明。  
标签可以不用。但是最好要用，提高代码可读性，对

文档注释最重要的在于它的**标签**。标签可以标注其后的内容是什么意思。

| 标签          | 用途     | 示例                            |
|-------------|--------|-------------------------------|
| @param      | 方法参数说明 | `@param username 用户名`         |
| @return     | 返回值说明  | `@return 操作是否成功`              |
| @throws     | 异常说明   | `@throws IOException 当文件不存在时` |
| @see        | 参考链接   | `@see OtherClass`             |
| @deprecated | 标记已过时  | `@deprecated 请使用新方法`          |

## 注解

注解不是注释，而是一种特别的标记，用于在编译时提醒JDK进行额外检查。

注解形如`@注解名(实参)`。这与上面的文档注释标签很像，但是又本质上的不同。注解出现在代码中，如示例代码中的
```java
@SuppressWarnings("all")
protected final List someList = new ArrayList();
```
`@SuppressWarnings`是一个非常常用的注解，可以抑制JDK爆警告。

注解的声明读者暂时不需要注意，因为注解的生效涉及到比较深入的机制。

注解的实参允许零个、一个或多个。对于多个实参的注解，我们要求使用`变量名 = 值`的形式进行赋值，如  
`@Mod(value = ExampleMod.MODID, dist = { Dist.CLIENT, Dist.DEDICATED_SERVER })`
~~对这是NeoForge声明模组入点的注解~~

很多注解对其大部分变量都声明了默认值，所以我们可以不去对这些值进行赋值，如上面的`@Mod`就对dist变量设置了默认值`{ Dist.CLIENT, Dist.DEDICATED_SERVER })`。因此，上面的写法等价于：  
`@Mod(value = ExampleMod.MODID)`。

然后，使用注解时如果你只希望对其一个参数赋值，当这个参数名为value时，你可以直接省略。也就是说，上面的又等价于：  
`@Mod(ExampleMod.MODID)`

## 主类

类似于C艹的main方法，java也采用main方法作为程序入点。

Java的main方法定义如下：
```java
public static void main(String[] args) {
    /* 方法体 */
}
```

main方法可以放在任何位置的任何类中。拥有main方法的类即为程序入点，主类。
一般而言，一个项目只有一个主类。但是如果涉及服务端和客户端的分离(比如Minecraft)，则可以通过添加其他入点。
