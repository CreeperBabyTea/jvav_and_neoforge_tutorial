## 类？对象？实例？

在第一章第二节中，我们已经知道，Java的程序基本载体就是类。但是，以往我们使用的类从来都是"静态的"
工具类，从来没有为类创建一个实例。  
下面，我们开始研究类与对象的关系。

[完整示例代码](../src/tutorial/oop/basic/Cat.java)

```java
package tutorial.oop.basic;

public class Cat {
    public static final String SPECIES = "cat";

    private final String name;

    {
        System.out.println("Initializer Block!");
    }

    public Cat(String name) {
        this.name = name;
        System.out.println("Constructor!");
    }

    public String getSound() {
        return name + ":nya~";
    }
    /* ... */
}
```

如你所见，这是一个类。  
我们先讲解一下这个类都包含了那些东西：
`public static final String SPECIES = "cat";`  
这里定义了一个**静态**字段。
`private final String name;`
这一部分定义了一个**非静态**字段。
这里我们注意到，相比于之前的定义语句，我们在定义类成员变量时，也是可以使用访问限制修饰符来修改字段的公开性的。

```
{
    System.out.println("Initializer Block!");
}
```

这里是一个**初始化块**。初始化块分为分为两种，一种就是我们之前用到过的静态初始化块，另一种就是现在的实例初始化块。  
在一个新的对象被创建时，初始化块会在构造器之前调用。

```java
public Cat(String name) {
    this.name = name;
    System.out.println("Constructor!");
}
```

这是一个**构造器**。构造器是直接用于创建实例的。你可以理解为，构造器就是一个"工作台"，它的形参就是"原料"，而产生的实例就是"
产物"。

那什么是一个实例呢？
我们再在这个类中添加一个main方法：

```java
public static void main(String... args) {
    var nachoneko = new Cat("Amashiro Natsuki");
    System.out.println(nachoneko.getSound());
}
```

运行这个方法，控制台上输出了：

```text
Initializer Block!
Constructor!
Amashiro Natsuki:nya~
```

在这个方法中，我们注意到了一个新的关键字：`new`。new后的`Cat(.....)`就是上面的Cat类的一个构造器。
这条语句中，我们"new"了一个新的Cat，并且将`name = "Amashiro Natsuki"`作为形参转递给了这个构造器，于是java便会分配一块内存来创建这个新的实例。
与此同时，这个新的对象的地址便传递到了变量nachoneko中。  
到这里你应该能意识到了，构造器其实类似于一种特殊的方法。它的"返回值"是我们创建的，该类的实例。
同时，调用构造器必须使用new关键字。

那么，我们可以初步理解到，类是其实例的模板，对象是某一个类的一个实例。类只有这一个，但是一个类的实例可以有无数个。
在上面的过程中，我们有一个类Cat，通过new关键字创建了它的一个实例，这个实例就是我们操作的一个对象

## 初始化块与构造器

在上面的程序中，其实你应该已经能看到，在一个对象的创建过程中，实际上执行顺序是：
`字段声明->初始化块->构造器`  
这个流程中我们要完成所有final实例字段的赋值，否则编译器会报错。

现在我们考虑，如果我们需要为"野猫"创建实例，因为野猫是没有名字的，所以我们将其命名为"wild"。这时创建对象的语句应该是：
`new Cat("wild")`  
但是，当我们需要创建成百上千个野猫的实例时，每个都打一遍wild不仅很麻烦，而且有打错的风险。

我们可以在Cat中添加如下代码：

```java
public Cat() {
    this.name = "wild";
    System.out.println("Constructor!");
}
```

这显然是一个无形参的构造器。并且将name设置为我们需要的值。这确实解决了当下问题。

但是，随着程序的升级，我们在构造Cat对象时添加了新的功能(比如一些日志功能等)
，那么我们必须修改所有构造器的代码，否则就会出现日志就会出现遗漏。  
这又是一个问题，即使是复制粘贴，这也很浪费时间，且不能保证不遗漏。

此时我们就可以引进新特性：构造器重载。
我们将刚才添加的构造器改为这样：

```java
public Cat() {
    this("wild");
}
```

这里`this(...)`的意思是，我们去调用这个类的其他构造器。于是乎调用新构造器时，这条语句会转而调用原有构造器，并传入"wild"作为形参。

## this?

我们看回代码，不难注意到在访问字段`name`时，我们在构造器中使用了`this.name`，但是在getSound中却直接使用了`name`
。这是为什么？  
其实，这两者调用效果是相同的。this关键字指代本对象，我们之前已经讲到过，点(`.`)可以表示"所属关系"，比如使用`System.out`
来访问System类的静态字段`out`。
这里是一样的，因为构造器中我又声明了一个形参name，为了区分，便对本对象的name使用this，强调了我们将形参name赋值给本对象的字段name。

既然this可以指代自身，那么this的用途就很多了。比如我们假设存在一个Shelter类，其中包含一个静态方法如下：

[代码](../src/tutorial/oop/basic/Shelter.java)

```java
public static void host(Cat cat) {
    System.out.println(cat + " is in this shelter!");
}
```

我们可以在初始化块的最后一行添加这样的代码：
`Shelter.host(this);`  
现在整个初始化块看起来是这样的

```
{
    System.out.println("Initializer Block!");
    Shelter.host(this);
}
```

到这里读者应该能理解this的自指含义了。

## static?

之前我们一直都在回避在方法之外创建字段。到现在，我们必须直面恐怖的现实了。

static即静态修饰符，可以对类中除构造器外的任何成员进行修饰。static可以修饰的范围包括：

- 字段
- 方法
- 初始化块
- 内部类(这个在下一节讲到)

我们从最简单的静态字段讲起：  
静态字段是属于类的，而与之相对的非静态(实例)字段是属于实例的。也就是说，假如我们创建了三个Cat对象，每个对象都有其各自的name(
实例字段)，但是共用属于其类的SPECIES和sound(静态字段)。
由于类是唯一的，我们的内存中仅存在一个SPECIES和一个sound。如果某一个Cat实例修改了sound，那么其他cat访问sound时收到的就都是修改后的sound。

同样的理解可以应用于方法和初始化块。  
静态方法属于类，而非静态方法属于实例。  
静态初始化块在类被加载时调用(后面再说xie)，而实例初始化块在实例创建时被调用。

由于非静态成员是属于实例而非属于类的，所以在静态语境下，除非指定了实例作为对象，否则不可以直接访问实例成员。

```java
public class StaticDemo {
    private int aInteger = 10;

    public static illegalAccessDemo() {
        //System.out.println(aInteger);   //这里会报错，我就给你注释掉了
    }

    public static legalAccessDemo() {
        System.out.println(new StaticDemo().aInteger);   //这里是正确的，因为我们通过实例访问实例字段。
    }
}
```

## 垃圾回收

现在我们已经会创建对象了，那么我们怎么回收对象呢？  
答案是：不需要回收！

这是java的一个强大机制：垃圾回收。在系统内存不足时，java会自动回收所有失去引用的对象的资源来腾出内存。失去引用就是指，不再有任何变量引用这个对象。  
当然，我们也可以手动回收垃圾，调用`System.gc();`即可。但是一般而言，这是虚拟机会帮你完成的，你无需担心。
