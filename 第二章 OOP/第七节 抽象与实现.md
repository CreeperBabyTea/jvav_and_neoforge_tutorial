## 抽象类

在上一节我们提到了，对于有**相同或相似行为**的类，我们可以采用继承的方法，以实现方法的复用。

同时，学习完上一节的多态，你也应该基本能认识到继承对于处理"不确定类型"的对象的作用。

现在我们介绍抽象类：

**抽象类**是一种特殊的类(废话)，其具有如下特点：

- 允许拥有**抽象方法**(也允许没有抽象方法)
- 不可以实例化，无论是否有抽象方法、无论是否有公开的构造器

声明一个类为抽象类很简单，只需要使用`abstract`修饰符即可，如下：  
`其他修饰符 abstract class 类名 {/*类体*/}`

无论何时，abstract和final关键字不共存。

### 抽象方法

抽象方法是一种特殊的方法(又是废话)。抽象方法没有方法体。与抽象类相同，抽象方法的声明也很简单：  
`其他修饰符 abstract 返回值类型 方法名(形参列表);`  
对直接分号结束，没有方法体。

一样的，抽象方法不能被final修饰，也不能被static或private修饰(静态方法无覆写，私有方法无权限)

### 抽象类的实现

一般而言，抽象类均可以被继承。也就是说，一般的抽象类都会有暴露的构造器。但是，仅从语法上来讲，抽象类的所有构造器均对外封闭也是被允许的。
这涉及程序设计思路问题，读者可以自行询问ai。ai提示词：
> Java中，仅从语法上讲，是否允许抽象类的所有构造器均对外封闭？
> 如果抽象类的所有构造器都是private的，会有什么特殊现象或者特别作用？

抽象类被继承时，继承的类必须符合下列二者之一：

- 同为抽象类
- 实现所有抽象方法，此时称该子类时该父类的**实现**

我们先将实现。实现，就是子类覆写父类的全部抽象方法。

比如，我们有一个类Shape，代表平面一个几何图形。这个类要提供计算周长和面积的方法，但是对于不同几何图形，我们有不同的计算方法
此时，我们将这两个方法设为抽象，同时在其子类中进行实现。作为例子，我们添加Circle和Rectangle两个类

这里请读者自行参考tutorial.oop.abstraction_and_implementation.abstract_class下的类

如果这个类也是抽象类，那么他就继承了父类的所有抽象方法。其子类实现这个子抽象类时，也要实现父类的抽象方法
> 说白了就是：  
> 现有抽象类A，抽象类B继承自抽象类A，C是B的实现  
> A中存在抽象方法method1，B中存在抽象方法method2，则C中需要同时实现method1和method2。

嗯，应该讲清楚了

抽象类代表某一大类具有共同行为(能计算面积和周长)的事物(几何图形)，但是具体事物(三角形、矩形等)如何进行这些行为则是未知的。
这也就是为什么抽象类本身不能直接被实例化，因为我们尚不知道这些行为该如何完成。

## 接口

接口是一种抽象程度更高的特殊类。接口的声明语法如下：
`其他修饰符 interface 接口名 {/*接口体*/}`

接口特点比较多：

- 一切字段默认被`public static final`修饰。也就是接口不允许实例字段存在、不允许非public以及非final字段的存在。
- 一切方法默认被public abstract修饰
    - 如果方法被default修饰，则会去除其abstract修饰符，成为默认实例方法。这里的default没有额外作用，访问依然是public。
    - 如果方法被static修饰，则去除其abstract修饰符，成为静态方法
    - 如果方法被private修饰，则去除上述一切限制，而是变为正常的私有实例/静态方法(java 9+)

实现接口使用implement关键字。这个写法和extend一样，就是`..... implement 接口1, 接口2, ...`。
没错，同一个类只能继承自一个父类，但是可以实现多个接口，更可以既继承自一个父类，又实现乱七八糟的接口。
这些接口同样有多态特征，即你可以讲接口的实现类型的对象作为接口类型使用。比如，实现了`ItemLike`接口的`Block`、`Item`、
`ItemStack`等，均可当作`ItemLike`类型使用。

接口的抽象程度比抽象类更高，以至于它连实例字段都没有。接口更多是提供了一种"规范"，而非一种"类型"。

接口也可以继承另一个或多个接口。接口之间使用extend表示继承关系，且允许多继承。

## 内部类

对，字面意思

就是类中之类

内部类分为四种：成员内部类、静态内部类、局部内部类、匿名内部类

其中，局部内部类就是定义在代码块中(如构造器、初始化块、方法)的内部类，不允许访问控制和static修饰符。局部内部类的静态与否，取决于其语境静态与否

静态内部类需要用static修饰，其行为与普通的类完全一致。静态内部类可以访问其外部类的私有成员。访问静态内部类语法为：
`软件包名.外部类名.内部类名`。一般的，我们的import语句直接导入外部类，并使用`外部类.内部类`来访问它即可

成员内部类，他是"非静态的"，也就是说，创建成员内部类必须是对一个对象创建。与静态内部类不同，既然成员内部类是非静态的，那么它就可以访问其所属外部类对象的实例字段和实例方法
创建成员内部类需要对一个实例创建

### 匿名内部类

如果说你需要实现一个抽象类或接口，但是这个实现这辈子就只会用到这一次，以后再也不会访问，那么单独为其开一个类会很麻烦。

因此我们可以使用匿名内部类。匿名内部类只能用于创建对象，其语法如下：

```
new 父类名(父类构造器参数列表) {
    /*类体*/
}
```

这里需要注意，我们声明匿名内部类的同时，创建其实例并"销毁"这个类。这里的销毁不是说它不存在了，而是你再也访问不到这个类了

匿名内部类由于只能指定父类型，所以不能进行多继承，也没有构造器。但是允许使用初始化块

如果父类是抽象的(比如接口或抽象类)，则你需要照常覆写其抽象方法

匿名内部类可以访问其上文的局部变量，但是这些局部变量必须是final修饰或等效于final修饰，也就是说，在初始化后再也没有被修改过的

举个不恰当的例子：对于之前讲的Shape类，我们可以如下创建其一个子类：

```java
            return 0;
        }

        @Override
        public double getSize() {
            return 0;
        }
    };
}
```

## lambda表达式

对，λ。讲这个之前介绍一个简单的概念：函数时接口。
如果一个接口只有一个抽象方法，那么这个接口就是一个函数式接口。就这么多

上面我们讲到，可以使用匿名内部类来快捷地创建抽象类或接口的一次性子类。这里我们介绍一种更简洁的写法：

已知函数式接口：

```java
public interface BiCalculator {
    double calc(double val1, double val2);
}
```

那么下面的匿名内部类可以创建其对象：

```java
var add = new BiCalculator() {
    @Override
    public double calc(double val1, double val2) {
        return val1 + val2;
    }
};
```

而下面lambda表达式的与上面的匿名内部类等效：

```java
BiCalculator add = (double val1, double val2) -> {
    return val1 + val2;
};
```

这里我们应该注意到了，lambda表达式必须显示指定类型，而不能使用var关键字(因为不同函数式接口可能有签名一致的抽象方法)

然后我们看lambda表达式的内容

`(double val1, double val2)`就是抽象方法两个形参。这里不一定要和声明的名称一致，只要保证参数数量一致和类型一一对应即可。这里可以省略显式指定类型，那么类型就是和接口中声明实一致
然后箭头就是标识符，没啥别的意思，嗯。然后大括号就是方法体

其次，lambda表达式中，如果只有一个返回语句，那么这条语句允许简化为：

```java
BiCalculator add = (val1, val2) -> val1 + val2;
```

对，然后如果只有一个形参，则可以进一步省略圆括号：

```java
Int2IntFunction add1 = val -> ++val;
```

### 方法引用

java.lang.Math中包含静态工具方法`double pow(double a, double b)`，作用是返回a^b(这里就是乘方，不是位运算)。

用这个方法实现上面的接口，可以写作：

```java
BiCalculator power = (val1, val2) -> Math.pow(val1, val2);
```

这里我们可以直接使用方法引用：

```java
BiCalculator power = Math::pow;
```

应该很容易看懂吧，就是形参列表和返回值一致，就可以引用。这里的`::`就是方法引用的标识符，而标识符前面的是方法的所有者，后面是方法名。
方法的所有者允许类与实例，也就是说，实例方法也是可以被引用的。方法名允许方法和构造器。特别的，引用构造器时，表达式的返回值是该类的一个对象，写作`类名::new`。对
